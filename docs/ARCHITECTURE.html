TECHNOLOGY JUSTIFICATIONS

Python

Core Language

Python dominates quantitative finance for good reason: pandas/numpy for time-series manipulation, scikit-learn/XGBoost for ML, and the largest ecosystem of trading libraries (ccxt, ta-lib). The GIL is irrelevant here — the bot is I/O-bound (API calls), not CPU-bound.

Rejected: Rust/C++ (unnecessary latency optimization for 30s cycles), Node.js (weaker ML ecosystem)

Binance CEX

Exchange

Highest global liquidity across altcoin pairs, robust REST + WebSocket API, maker fee as low as 0.075%. The ccxt library abstracts the API, making future exchange migration trivial. Binance's order book depth minimizes slippage on micro-account position sizes.

Rejected: DEXs (higher fees, MEV risk), Bybit/OKX (lower liquidity on target pairs)

Multi-Brain Consensus

6 Independent Analysis Brains

No single strategy wins in all market conditions. The 6-brain architecture (technical, order flow, AI, multi-timeframe, correlation, ML) provides diversified signal sources. The 4/5 consensus requirement with veto power filters false positives — a brain that strongly disagrees can block a trade even if 4 others agree.

Rejected: single-strategy (fragile), majority-only voting (no veto for high-conviction dissent)

ChromaDB + RAG

Vector Memory

Every trade is stored as a 16-dimensional market state vector. Before each new trade, the system retrieves the 5 most similar historical situations by cosine similarity. This gives the AI brain concrete precedents — "last time the market looked like this, we lost 2.3%" — rather than generic reasoning.

Rejected: SQL lookups (can't capture multi-dimensional market similarity), no memory (repeats mistakes)

XGBoost

ML Classification

Gradient-boosted trees handle the tabular, feature-engineered nature of trading data better than neural networks at this data scale. XGBoost trains in seconds on 30 features, supports walk-forward validation (essential for non-stationary financial data), and provides feature importance for interpretability.

Rejected: LSTM/Transformer (overfits on small datasets), logistic regression (too simple for feature interactions)

Gemini AI

LLM Analysis Brain

The AI brain uses Gemini to synthesize market conditions into natural language analysis, augmented with RAG context from past trades. This captures qualitative patterns (market regime changes, correlation breakdowns) that purely quantitative brains miss. The free tier supports the 30-second cycle budget.

Rejected: GPT-4 (higher cost per call), local LLM (insufficient reasoning quality)

Quarter-Kelly Position Sizing

Risk Management

Full Kelly criterion maximizes long-term growth rate but produces volatile drawdowns. Quarter-Kelly reduces position sizes to 25% of the Kelly-optimal, sacrificing ~12% of theoretical returns for ~75% reduction in drawdown variance. Critical for micro accounts where a single bad trade can be catastrophic.

Rejected: fixed percentage (ignores edge quality), full Kelly (unacceptable drawdowns on $20–100 accounts)

Oracle Cloud (Always Free)

Deployment

Oracle's Always Free tier provides an ARM VM with 24GB RAM and 4 OCPUs — permanently free, not a trial. This runs the bot 24/7 with zero infrastructure cost. The ARM architecture handles Python workloads efficiently, and the generous RAM accommodates ChromaDB's in-memory vector index.

Rejected: AWS/GCP free tier (expires after 12 months), home server (uptime unreliable), Heroku (no free tier)

Limit Orders Only

Execution Strategy

Market orders pay taker fees (0.1%) and suffer slippage. Limit orders pay maker fees (0.075%) and guarantee fill price. On a micro account, the 0.025% fee difference per trade compounds significantly over hundreds of trades. The 30-second cycle provides enough time for limit order fills.

Rejected: market orders (higher fees + slippage), mixed (complexity without proportional benefit at this scale)

5-Layer Protection

Autonomous Safety

Each layer operates independently: L1 (per-trade stop-loss/take-profit), L2 (session pause after consecutive losses), L3 (portfolio-wide exposure limits), L4 (black swan detection with emergency exit), L5 (auto-recovery after cooldown). If any single layer fails, the others still protect capital. No human intervention required.

Rejected: single stop-loss (insufficient for cascading failures), manual oversight (defeats 24/7 autonomy)
